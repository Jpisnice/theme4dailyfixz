## What will be built

Home, collection and collection-list templates rebuilt on the sprint 01 design system. Sprint 01's `price`, `badge`, `product-card` and `section-heading` snippets stop being orphans in this sprint.

**Where merchant-editable values live (templates are Liquid, not JSON)**
- **Block settings** (`block.settings.*`, schema defaults, read inside each block): all home content. Heading, subheading, image, link, text, collection, product count and colours of each home block. Home blocks are invoked from `templates/index.liquid`; the order on the page is the order of the `{% block %}` calls in that file. Where a block needs content the caller cannot pass through the editor (for example which collection), the setting is a `collection` picker with a sensible fallback (see S9).
- **Theme settings** (`config/settings_schema.json`, new group "Collection pages", stored in `config/settings_data.json`): `collection_products_per_page` (range, default 24), `collection_columns_desktop` (select 3 or 4, default 4), `collection_show_filters` (checkbox, default on), `collection_show_count` (checkbox, default on). Mobile is always 2 columns. Collection and list-collections templates read these because templates cannot expose per-instance settings.
- Tests that need a different value edit `config/settings_data.json` (theme settings) or the block's schema default (block settings), as in sprint 01.

**New files (names are indicative; the contract binds behaviour, not file names, except where a criterion names one)**
- Home blocks in `blocks/`: `hero`, `featured-collection`, `collection-tiles`, `trust-strip`, `brand-story`, `newsletter`.
- Collection blocks in `blocks/`: `collection-banner` (title, description, image), `collection-toolbar` (result count, sort, filter button), `collection-filters` (storefront filters, active pills, clear all), `collection-grid` (product-card grid, empty state, pagination).
- Snippet `snippets/pagination.liquid` (numbered prev/next pagination from the `paginate` object, `{% doc %}` header).
- `assets/collection.css`, `assets/home.css` (or additions to `base.css`), and `assets/collection.js` (dependency-free ES module; filter drawer on mobile, auto-submit on change; no Liquid, config via `data-*`).
- Templates rewritten: `templates/index.liquid`, `templates/collection.liquid`, `templates/list-collections.liquid`. They keep composing with `{% block 'container' %}` where a contained width is wanted; full-bleed blocks such as the hero may sit outside it.
- Locale keys in `locales/en.default.json` and `locales/en.default.schema.json` for every new string and editor label.
- `.theme-check.yml`: the `OrphanedSnippet` ignore list is deleted.

**Behaviour in short**
- Home works with zero configured content: each block shows a designed placeholder (placeholder SVG, sample copy from locale keys) and no block outputs an empty wrapper, heading or link.
- Collection filtering is progressive: filters and sort are plain GET forms/links that work without JS; JS only auto-submits on change and runs the mobile drawer.
- Filters are hidden gracefully when Search and Discovery has no filters configured (`collection.filters.size == 0`); sort and grid still work.
