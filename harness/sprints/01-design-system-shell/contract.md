## What will be built

Foundation that every later sprint inherits, plus the global shell around `{{ content_for_layout }}`.

**Where values live (answers to review item 2)**
- Blocks invoked statically from `layout/theme.liquid` cannot be edited block-by-block in the theme editor, so everything a merchant or test must change lives in **theme settings** (`config/settings_schema.json`, stored in `config/settings_data.json`): announcement text, link and colours; logo and logo width; footer blurb; social URLs; all colours, fonts, radii. Blank vs set for the announcement bar is therefore tested by editing `settings.announcement_text` in `settings_data.json`.
- Menus are `link_list` settings in the block schemas (`header`: `menu`, default `main-menu`; `footer`: `menu_1`..`menu_3`, `menu_1` defaults to `footer`; plus `show_payment_icons`), read as `block.settings.*`.
- The `container` block **stays**, for templates only. It is **no longer wrapped around the header or footer**: it is a CSS grid whose box is only as tall as its content, which would stop `position: sticky` on the header from working. Header and footer constrain their own inner width with a `.page-width` helper that uses the same `--page-width` and `--page-margin` tokens.

**Design tokens and settings**
- `config/settings_schema.json`: groups for colours, typography (heading font and body font), shape (corner radius, button radius, product card image ratio), layout (page width, page margin), logo (image, width), announcement bar, footer (blurb), social links (six URLs). `config/settings_data.json` carries the warm "everyday, done well" defaults: warm off-white, warm near-black, one tomato accent, a serif display heading face over a Work Sans body.
- `snippets/css-variables.liquid` (now with `{% doc %}`): emits colour, font, radius, 4/8px spacing scale, card ratio, tap size and focus tokens as `:root` custom properties; accent hover is derived with Liquid colour filters.
- `snippets/meta-tags.liquid`: gains a `{% doc %}` header only (no behaviour change).
- `assets/base.css`: reset additions, type scale, accent-underline heading motif, `.page-width`, forms, buttons, badges, price, product card, section heading, visually-hidden, skip link, focus-visible, reduced motion, announcement bar, header, footer. Legacy rules for existing blocks are kept but re-expressed with tokens. `assets/critical.css` keeps its reset and gains token-with-fallback body styles and above-the-fold skeleton rules.

**Base snippets** (new, each opens with `{% doc %}`): `icon`, `button`, `price`, `badge`, `product-card`, `section-heading`, plus `social-link` (helper for the footer).

**Shell**
- `blocks/announcement-bar.liquid` (new): slim bar, text and optional link from theme settings, renders nothing when text is blank. No dismiss button.
- `blocks/header.liquid` (rewritten): sticky, compact; logo image (if set) else `shop.name` wordmark; main menu with nested links; search link (`routes.search_url`); account link (`routes.account_url`, only when `shop.customer_accounts_enabled`); cart link (`routes.cart_url`) with count. Below 768px the menu panel becomes an off-canvas drawer opened by a toggle button. At 375px the header row shows menu button, wordmark, search and cart; the account link lives inside the drawer.
- `blocks/footer.liquid` (rewritten): up to 3 link-list columns plus a brand/blurb column, newsletter (`{% form 'customer' %}`), social links, payment icons, localization selectors, copyright line.
- `layout/theme.liquid`: skip link first in `<body>`, then announcement bar, header, `<main id="MainContent">`, footer; loads `base.css`; sets a `js` class on `<html>` from a tiny inline script.
- `assets/header.js` (new, dependency-free ES module, config via `data-*`): drawer, submenu accordion, desktop dropdown Escape handling, cart count refresh on `cart:updated`.
- Locale keys in `locales/en.default.json` and `locales/en.default.schema.json` for every new string and editor label.

**No-JS behaviour (review item 4)**: server-rendered markup contains every top-level and nested link. Without the `js` class on `<html>`: the toggle button and close button are `display: none`, the drawer panel is an ordinary in-flow block under the header row on mobile (not off-canvas, not `hidden`), all submenus are expanded, and the header is `position: static` below 768px. With JS, the `js` class turns the panel into an off-canvas drawer and enables toggles. At 768px and up the nav is inline and dropdowns open with CSS `:hover` and `:focus-within`, no JS needed.

## Generator notes (disagreements and decisions)

- Item 3: S2, S3 and S5 now lean on `npm run check:dialect`; only ordering and root-attribute checks remain as grep.
- Item 7: token names are required by category only, except `--tap-size`. The S8 note about `\|` is because in `grep -E` an unescaped `|` is alternation; the draft's escaped form was the bug.

### Round 1 (evaluator): changes requested, status stays DRAFT

Overall the scope is faithful to features 1 and 2 and most criteria are checkable. Seven changes, in priority order.

1. **S1 is wrong against the baseline.** `npm run check` today already reports 2 dialect warnings (`snippets/css-variables.liquid` and `snippets/meta-tags.liquid` lack `{% doc %}`), so "0 warnings" cannot be met unless both are fixed. Reword: 0 errors, and 0 warnings after the sprint (explicitly requiring `{% doc %}` on `css-variables` and `meta-tags`, which the sprint touches anyway). Drop the "introduced by this sprint" phrasing, which contradicts the verify column.
2. **Where do announcement-bar and header settings live?** Blocks in `layout/theme.liquid` are invoked statically, so state how a merchant sets the announcement text, link and colours (block schema defaults, parameters, or theme settings) and how B5/B14 are exercised. B5 says "toggle the setting in the theme editor", which no agent or Playwright run can do. Rewrite B5 so blank vs set is tested by editing the stored value (`settings_data.json` or the block default), and add a static criterion naming where the value is read. Also state whether the existing `container` wrapper block stays; S5 ("order announcement bar, header, main, footer") is ambiguous about it.
3. **S2 command is broken as written** (`\|` is a literal pipe in `grep -E`, so it matches nothing). `scripts/dialect-check.mjs` already enforces no stylesheet/javascript, no presets, `{% doc %}`, `shopify_attributes` and `{% block` placement. Make S2, S3 and S5 simply "`npm run check:dialect` exits 0" plus the `test ! -d sections` and no-JSON-templates checks; keep only the order check from S5 as grep.
4. **S15 (no-JS fallback) is not testable as phrased** ("`<noscript>` or `<details>`" is a choice, not a criterion). Define the behaviour: with JS off, every top-level and nested menu link is present in server-rendered HTML and reachable, and state how (for example the drawer panel is not `hidden` by default and JS adds the hidden/closed state, or a `<noscript>` style). 5. **Spec features not covered by any criterion.** Add concise criteria for: footer link-list columns (up to 3 menus plus brand/blurb column, columns omitted when a menu is empty), social links render only for URLs that are set, payment icons render from `shop.enabled_payment_types` and hide when empty, copyright line; header search link uses `routes.search_url`, cart link `routes.cart_url`, account only when `shop.customer_accounts_enabled`. 6. **Originality is unguarded.** The design direction asks for a distinctive display face and a tomato/marigold accent, but S9 and S24 only require that settings exist. Add: default `type_header_font` differs from the body font default, and the accent-underline heading motif is implemented in `base.css` and used by `section-heading` (grep for the class in both).
